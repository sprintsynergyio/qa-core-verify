# Changelog

## Unreleased

- A fault that never reaches a page is `not-run` and does not raise QCV-F002, QCV-F003, or QCV-F004. `browser.newContext()` and `browser.newPage()` get the init script and `context.route`. `page.setContent` runs the DOM script again. A fault id `blank-app` whose type is not `blank-app` exits 2 before the temp copy. The SauceDemo locator-evidence live test compares `.qa-core` with the directory that was already there.
- `--only faults` runs QCV-F002, QCV-F003, and QCV-F004. `blank-app` is built in. Other faults come from `qa-core-verify.faults.json`. The report has a fault matrix per test. A `change-text` fault that should show a selector, and still matches nothing, raises QCV-L002 to error. The DOM-mutation idea is credited in RESEARCH.md. This checker does not claim to be that paper's framework.
- A read-only spec in the temp copy is made writable. If a write still fails, that assertion is `error` and the inversion run continues. `--keep-workspace` prints `Workspace:` when the copy is kept after an error. A `--config` directory with no `playwright.config.*` says so. The inversion plan is printed after the control runs. `inversion.mutants` is documented in docs/report-schema.md. A `skipped` inversion outcome does not lower the row. A broken config names the project file, not the temp copy. Baseline is printed before the mutant runs. A namespace import of a relative fixture, a `const` alias of `test`, and `(0, test)()` are inventoried. An anonymous `test.describe` adds no title. `test /* comment */ (` records the parenthesis column. `frameLocator().owner()` is recorded. A test that fails only in the evidence run prints a reason. A suite that fails to load exits 2 and prints the load error. CI caches the Playwright browser download and gives the install step its own budget.
- A locator record with a column or a title that matches no test on that line is not attached to the other tests on the line. Every remaining test receives the record only when both the column and the title are absent.
- Inversion reads Playwright's test status. An expected `test.fail()` that still fails is `survived`. An unexpected pass is `killed`. A project that passed, with the others skipped, is `survived`. A test that does not pass its own `<file>:<line>` run is not inverted. `expect` imported from a relative fixture is inverted. A same-line locator stays on the test that recorded it. `locator().contentFrame()` stays synchronous and wraps the `FrameLocator`. A test that fails the evidence run is `not-run`, not trusted.
- `--config .` is the project directory and is accepted when that directory holds a `playwright.config.*` file. A directory with no `playwright.config.*` exits 2 before the copy. Playwright would use defaults for that directory. Report rows sort by file, then by line and column as numbers. `testIgnore` is read when it is a string, an array, or a regex. An unreadable `testIgnore` adds `testIgnore was not applied` to the discovery line and does not drop the rest of the config. A `.mjs` or `.mts` spec imports `qcv-locator-fixture.mjs`. An evidence run that exits non-zero with no records marks those rows `not-run`. Baseline failures are keyed by file, line, and column. `locator().contentFrame()` and `expect.configure()` are recorded. `.nth(index)` and an array `toHaveText` or `toContainText` whose length equals the match count are not QCV-L003. `not.toBeVisible({ visible: false })` is not an absence check. A directory-link copy stops when the copied bytes pass the cap. Both CI jobs set `timeout-minutes: 15`.
- `--only inversion` runs QCV-F001. One assertion is inverted at a time in a temp copy. `.not` is added or removed. `.soft` and `.poll` stay. `toPass` and a custom matcher are skipped as info. `killed` is a failed inverted test. `survived` is QCV-F001. `timeout` and `error` are not counted as good. `--max-runs` stops early and lists the rest as `not-run`.
- The baseline runs with `--retries=0`, so a test that fails its first attempt unexpectedly is `baseline-red` even if retries would make it pass. An expected `test.fail()` failure has status `expected` and is not `baseline-red`. See the next bullet.
- `test.fail()` that fails as expected has Playwright status `expected`. The Baseline line counts it as passed, and locator findings still apply. `test.fail()` that passes has status `unexpected` and is `baseline-red`. A test skipped in one project and run in another keeps the findings from the project that ran. The row is `not-run` only when no project ran it, and `baseline-red` when any project failed it.
- A test the baseline report marks skipped is `not-run`. That includes `test.skip()` and `test.fixme()` in the body, `testInfo.skip()`, and a test `test.describe.serial` did not run after an earlier failure. `--config` that names a directory uses the `playwright.config` file inside it. A missing config is refused before the temp copy is made.
- Two `test()` calls on one line keep their locator findings. A TypeScript `test()` call is recorded on the character after `test`, and that column matches the inventory row. Evidence that still matches more than one row is reported on each of those rows, so none of them is trusted. `--only locator` reads the inventory from `--config`. A test with no baseline result is `not-run`. `toBeEnabled({ enabled: false })`, `toBeChecked({ checked: false })`, and `toBeEditable({ editable: false })` are not absence checks, because a missing element fails the test.
- A baseline failure under a subfolder `testDir`, or under two projects with different `testDir` values, is `baseline-red`. A symlink to a directory copied elsewhere is copied again. `toBeVisible({ visible: false })`, `toBeAttached({ attached: false })`, and `toHaveCount(0)` are absence checks. Startup does not delete temp directories. `--config` is resolved from the process cwd and refused when it sits outside the project. Parameterized tests match evidence by file and test line.
- `--only locator` runs QCV-L001 through QCV-L004. A baseline failure is `baseline-red` and gets no locator finding. Reports list each locator as `unique`, `ambiguous`, or `never-matched`. QCV-L002, QCV-L003, and QCV-L004 are active in the SauceDemo manifest. The live check runs when `QCV_LIVE=1`.
- Locator evidence keeps selector controls as `\u` escapes, drops query strings, records parent counts for `.first()`, `.last()`, and `.nth()`, and re-exports `@playwright/test`. `frameLocator` and pages from `context.newPage()` or a popup are wrapped. A broken evidence run with no records prints the Playwright output tail.
- `--only locator-evidence` records locator match counts in a temp copy of the project. The choice and the measurements are in `docs/decisions/0001-locator-evidence.md`.
- A locator action records the raw `count()` taken after the action returns. `resolvedOnAction` is true when that strict action returned. Record order does not use `matchCount`. The temp copy follows symlinks, and a rewrite is refused unless the file is a regular file inside that copy. `project.dir` drops control characters and bidi overrides. `--json`, `--format`, and `--fail-on` exit 2 with that mode. SIGINT, SIGHUP, and SIGTERM stop Playwright and Chromium, then remove the temp copy. A repeat of those signals during cleanup is ignored. Chromium's temp files are created in a unique directory beside the project copy, and that directory is removed with the run. The copy includes the project's own files, including a directory named `.qcv-tmp`. With `--keep-workspace`, the kept directory is `qcv-run-XXXXXX` and it contains `project`. The `.qcv-browser-` sibling is removed even when that directory is kept. A normal finish, SIGINT, SIGTERM, and SIGHUP each print `Workspace: ` plus that absolute path on stderr. A backslash in the path is doubled. C0, DEL, C1, U+2028, U+2029, and bidi controls (U+200E, U+200F, U+202A through U+202E, U+2066 through U+2069) are then escaped as `\u` plus four lowercase hex digits. The path is not shown with `~`.
- When `--out` is outside the project, the console prints that path as it was typed.
- Evidence and fix hints drop C1 controls and bidi overrides before they are printed.
- The HTML rule filter hides a whole test when none of its rules are checked.
- A const alias of `expect.soft` is a soft assertion. `let` and `var` are not followed.
- QCV-W006 still flags a presence-only assertion when a click is followed by `page.goto`.
- QCV-W003 uses one fix hint for an unawaited assertion and an unawaited call.
- A row is trusted when it has no warn or error finding. Review means a warn. Untrusted means an error. Skip, fixme, and describe.skip stay not-run.
- Report paths are relative to the project folder. `project.dir` is the folder's base name.
- Markdown escapes titles, file names, and messages. Timestamps use local time and its offset. Reports name the checks that ran.
- Write a console report, a JSON report with schemaVersion 1, a Markdown report, and a single-file HTML report.
- QCV-W003 flags an unawaited async helper and an unawaited test.step block that contain an assertion, and it flags unawaited resolves and rejects matchers. An awaited then, catch, or finally chain is waiting. The message says the async assertion is not awaited.
- A const alias of expect in the file, a describe callback, or the test is treated as expect.
- QCV-W008 treats a catch that throws only inside one branch of an if as swallowing the other path.
- page.goto is not a user action for QCV-W006.
- test.describe.skip produces one finding for the block, including when the block has no tests.
- Treat an awaited or returned Promise.all, Promise.allSettled, and test.step as waiting for the assertion inside it.
- Follow locator and page read fields on a page object, including constructor assignments, initializers, and getters.
- Flag every unawaited async matcher, including expect.poll, without requiring the subject to be a locator or a page.
- Do not flag a loop over a non-empty array literal, or over a const in the same test bound to one.
- Add static weak assertion rules QCV-W000 through QCV-W010, with one file per rule and good and bad fixtures.
- Follow one relative import into a helper or page object. A second import is QCV-W000 when the call could be an assertion or a locator.
- Scaffold the TypeScript CLI, the spec inventory parser, and rule QCV-W001 Test Has No Assertion.
- Do not inventory a test call inside a hook callback or a timer callback.
- Add a SauceDemo demo suite, an expected-findings manifest, and a golden test for active findings.
